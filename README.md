# Robotic-Desk-Assistant-Tick-Mk.-1-
Everything about my first personal project "Tick Mk. 1"
# Overview
Tick Mk. 1 is designed to be a small desk companion that sits on your workspace while you study. It is programmed to have 4 screens: a face, a Pomodoro timer, a breathing exercise, and a fidget toy. The user can cycle through all 4 of these screens by physically rotating the robot in 90 degree increments. I did this project during my college freshman year summer and learned KiCad, C, and Autodesk Fusion from scratch during that time period. Thank you to Phil's Lab on YouTube for teaching the KiCad basics, Bro Code on YouTube for his excellent C tutorial, and afiskon on GitHub for the SSD1306 STM32 library.
# PCB Design
It is true that this project can successfully be completed on an Arduino or other development boards with much less effort and cost, but I opted for a custom PCB for two reasons. My main reason is that, since this is my first project, I wanted to make a custom PCB so that I can get experience in KiCad and coding in C. My second and more practical reason is that I wanted to make the robot as small as I could, so using an Arduino would significantly increase the total volume the robot occupies. 

For the PCB, I used an STM32F103 microcontroller as STM has an excellent suite of coding applications (STM32CubeMX, STM32CubeIDE, and STM32CubeProgrammer) and ample online resources that allow me to focus on coding only the main logic of the robot instead of spending time doing the low-level configurations. I was initially considering a STM32F411 chip as it had lots of memory and a high execution frequency, but I was able to snag some STM32F103 chips for free at my job over the summer, so I dropped the STM32F411s pretty quickly. To get the STM32 operational, I used a 8MHz external crystal to be stepped up to 72 MHz using the microcontroller's PLL. I also used 2 100K ohm resistors on PA8 as a voltage divider for VBUS sensing. I also set up a pi filter on the VDDA pin to get a super clean power signal. The pi filter is composed of two capacitors and a ferrite bead. As the line travels through the pi filter, high frequency noise is shunted into ground by the first capacitor as higher frequencies result in lower impedances for capacitors. As it travels through the ferrite bead, even more high frequency noise is shaved off as ferrite beads let lower frequencies pass like a near-zero resistance wire but act as a resistive filter to higher frequencies. The second capacitor shunts off even more high frequency noise, and what results is a clean power signal that can be used for the VDDA line.

I wanted the robot to be powered with a battery, so I included a BQ24090DGQ and a USB-C interface for charging. I specifically used the BQ24090DGQ for its easy implementation and clear and thorough datasheet. For the USB-C interface, I also included a USBLC6-2P6 electrostatic discharge (ESD) protection diode array. Since the USB-C port interacts with the real-world frequently, it is possible for there to be a momentary but humongous spike of voltage in an ESD event that may damage the components of the board, so the diode array serves to shunt the massive ESD current safely while clamping the voltage to manageable levels.

Since I want the robot to sense its roll angle, I used the BMI323 IMU. It has options for I3C and SPI communication, but for simplicity, I used the I2C protocol. It also has a tap-detect engine that I used for the fidget toy (the user taps the case to draw circles randomly on the screen). For debugging and code upload, I included Serial Wire Debug (SWD). I also put in mounting holes so that I can use standoffs in the case to mount the PCB. For the screen, I used an 1.3" OLED breakout display I found on Amazon.

For the PCB footprint, I used a 2-layer board for simplicity. It's a relatively standard 2-layer board, but I made sure to use a ground pour on the front and back to simplify wiring. I also put in lots of stitching vias, which serve some pretty cool purposes. Since there are two ground pours, having the stitching vias physically connect the two pours, creating a more unified ground reference. The stitching vias also provide return current a quick way back to the source, which significantly reduces current loop area. Reduced current loop area reduces inductance as it reduces magnetic flux linkage. It also reduces EMI as having the signal and return lines run closer to each other allows some magnetic fields to cancel out, which reduces the amount that radiates outward as EMI.

# Code
I used STM32CubeMX to configure the pins. MX automatically generates the code for the configurations for you and puts in a file, and then you can transfer that file over to CubeIDE to start making your main logic.

The code is pretty basic. I made my own BMI323_Read function as the BMI323 first sends out some dummy bytes before sending real data, so I needed to filter those out myself. I also used software hysteresis to prevent state flickering on the screen. Roll readings are not perfect and flicker just above or just below the true reading, so having two states share the same boundaries (e.g. Pomodoro timer is activated when roll is within 90 degrees to 180 degrees, face is activiated when roll is within 0 degrees to 90 degrees) can cause rapid state changes as the readings fluctuate from just below 90 to just above 90 degrees. I used a complementary filter to get those roll angles. I made sure to fix the wraparound error and also utilized a dynamic alpha so that the readings had less latency. I wrote more information as comments in the code itself.

# CAD of Case
I didn't want to make something super complicated, so I just made a cube with chamfered edges. I hollowed it out and put in some standoffs for the OLED and the PCB so that they can be mounted. I also put in a power switch holder and made a cutout for the USB-C port. I also made it so that it would snap together using a snap case and lid.
